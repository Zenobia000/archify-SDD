ADR-0001: Deliver reminders through a transactional outbox

Long image

A

Answer

Booking API writes each appointment event to an outbox table in the same transaction as the appointment. An Outbox Publisher relays it to the Event Bus, and the Reminder Worker sends the reminders.

  1. A confirmed appointment and its event commit together, so no reminder is lost when the Event Bus or Messaging Provider is down.
  2. The booking request no longer waits for SMS or LINE delivery.
  3. The Reminder Worker owns the 24 h and 2 h schedule and its retries, apart from the Booking API.

Applies toCareSlot (fictional)reminders for confirmed appointmentsStatus: Accepted

1

What problem does this decision solve?

A visit is confirmed only after the deposit succeeds. Reminders must then go out 24 h and 2 h before the visit, by SMS or LINE. A confirmed visit is also pushed to the Clinic EMR.

The confirmation runs inside a Payment Provider webhook. That handler must answer fast and must not depend on a third service being up. The Messaging Provider can be slow or unavailable for minutes at a time.

The failure we must avoid

The appointment commits as confirmed, but the reminder request is never sent. The patient then misses the visit and forfeits the deposit through no fault of their own.

What did we decide?

Diagram structure
  • Booking API booking-api
  • Booking DB booking-db
  • Outbox Publisher outbox-publisher
  • Event Bus event-bus
  • Reminder Worker reminder-worker
  • Messaging Provider messaging-provider
  • booking-api → booking-db · one transaction
  • booking-db → outbox-publisher · unpublished rows
  • outbox-publisher → event-bus · AMQP
  • event-bus → reminder-worker · appointment.confirmed
  • reminder-worker → messaging-provider · SMS, LINE
  1. Booking API ↗

    Writes the confirmed appointment and an appointment.confirmed outbox row in one transaction.

  2. Outbox Publisher ↗

    Reads unpublished rows, publishes them, then marks them published.

  3. Event Bus ↗

    Delivers the event to every subscriber, including the Reminder Worker.

  4. Reminder Worker ↗

    Schedules the 24 h and 2 h reminders and sends them through the Messaging Provider.
